# Стол
1. Медет Парахат ВТ-24А
Маленький сайт с тремя простыми инструментами на каждый день:

- **Список дел** — добавляйте, отмечайте и удаляйте задачи.
- **Заметки** — один блокнот, который сохраняется автоматически.
- **Таймер фокуса** — отрезки по 25 / 15 / 5 минут.

Никакого бэкенда: всё написано на чистом HTML, CSS и JavaScript, все данные хранятся в `localStorage` браузера.

## Структура проекта

```
.
├── index.html                    # разметка страницы
├── css/
│   └── style.css                 # стили
├── js/
│   └── app.js                    # логика (вкладки, список дел, заметки, таймер)
├── .github/
│   └── workflows/
│       └── deploy.yml            # автодеплой на GitHub Pages
├── .gitignore
├── LICENSE
└── README.md
```

## Запуск локально

Файлы статические, поэтому достаточно открыть `index.html` в браузере. Либо поднять локальный сервер:

```bash
python3 -m http.server 8000
# затем открыть http://localhost:8000
```

## Как выложить проект на GitHub

### 1. Создайте репозиторий на GitHub

На github.com нажмите **New repository**, задайте имя (например, `desk`) и создайте его **пустым** (без README, .gitignore и лицензии — они уже есть в проекте).

### 2. Свяжите папку с репозиторием и отправьте код

Из этой папки выполните:

```bash
git init
git add .
git commit -m "Первый коммит"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<название-репозитория>.git
git push -u origin main
```

После этого любые дальнейшие изменения отправляются так:

```bash
git add .
git commit -m "Описание изменений"
git push
```

### 3. Включите автодеплой на GitHub Pages

В репозитории на GitHub откройте **Settings → Pages** и в разделе **Build and deployment → Source** выберите **GitHub Actions**.

Всё — в проекте уже лежит workflow `.github/workflows/deploy.yml`. Он срабатывает при каждом `git push` в ветку `main` и сам публикует сайт. Через минуту-две после пуша сайт появится по адресу:

```
https://<ваш-логин>.github.io/<название-репозитория>/
```

Ссылку также можно посмотреть на вкладке **Actions** репозитория, в последнем прогоне workflow, или в **Settings → Pages** после первого успешного деплоя.

### Дальнейшая работа

Теперь любое изменение файлов, закоммиченное и отправленное в `main`, автоматически обновляет живой сайт — отдельно ничего собирать и деплоить не нужно.
